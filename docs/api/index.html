DSH REST API (1.0.0)

Download OpenAPI specification:

URL: https://github.com/MRISS-Projects/dsh

The API that dsh-rest-api serves today: the two operations of DocumentResource, with the responses a running application returns. An API change starts here, as .github/copilot/rules/api-standards.md asks ("OpenAPI First").

Departures from api-standards.md. The API does not meet that standard yet, and this document says where:

  • Paths are under /v1/dsh/document, not /api/v1, and name actions (submit) rather than resources. No issue plans a change.
  • A failure the controller handles answers 200, with the failure in the body: a rejected submission and an unknown token. #138 plans the 4xx codes.
  • No request is authenticated, so each operation declares security: []. No issue plans authentication.
  • Errors that reach Spring Boot answer its default error body (ErrorBody), not the error body the standard describes.
  • The standard says never to expose internal error details, but a rejected submission's message carries the caught exception's own message. No issue plans a change: #138 changes the status codes, not the message.

Outside this document. /actuator/health and /actuator/info exist, served by Spring Boot Actuator. They are not DocumentResource's, and #45 owns them.

Submitting a document and reading its status

Submit a document for processing

Stores a document and queues it for processing, and answers with the token that identifies it.

A non-blank title must be supplied either as the title query parameter or as a multipart title part. OpenAPI 3.0 cannot enforce this requirement across locations.

  • /submit does not wait for the store or the enqueue. Both run asynchronously and race the response, so /status can answer TOKEN_NOT_FOUND for a moment (from the code; a live run never saw it in 20 tries), and a store that cannot be reached does not fail the submission. Wave 2 task 1 (specs/product/PRD.md) changes this.
  • Every submission gets a new token, the same file included.
  • The token is opaque to a client.
  • A rejected submission answers 200, with token ERROR and the reason in message: a blank title, or any exception the controller catches (#138).
  • The file's type is not checked. Its size is bounded by Spring Boot's multipart defaults, which the application does not change: 1 MB per file and 10 MB per request. A larger upload answers 500.

See specs/features/rest-api-endpoints.md and specs/features/document-analysis.md.

Get a document's status

Answers the status of the document a token identifies, and the status's message.

  • An unknown token answers 200, with status TOKEN_NOT_FOUND (#138).
  • A store that cannot be reached answers 500, after the store client's own timeout of about 30 seconds.

See specs/features/rest-api-endpoints.md and specs/features/indexing-workflow.md.
